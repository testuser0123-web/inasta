# 活動カレンダー

プロフィールの投稿タブ上に月別ドットカレンダーを表示します。アクセスは薄緑、通常の画像・動画投稿と公開した日記は濃い緑です。日本時間の投稿日で記録します。下書き・コメント・コンテスト投稿は対象外です。投稿や日記を削除しても日別活動は残ります。

プロフィール → その他の設定 → 活動カレンダーで「非表示」「自分にだけ表示」「全員に公開」を選択します。初期値は非表示です。非表示中も記録します。公開時は未ログインの閲覧者も確認できます。取得処理は毎回サーバーで公開範囲を確認し、日別フラグ以外の投稿内容を返しません。

## デプロイ手順

このリポジトリには既存のPrismaマイグレーション履歴がないため、既存DB向けの追加SQLを用意しています。`prisma migrate reset` やスキーマ全体の上書きは不要です。

1. DBのバックアップ・復元手段を確認します。
2. 対象環境の `DATABASE_URL_UNPOOLED` を安全な環境変数として設定します（リポジトリには保存しません）。
3. `node scripts/apply-activity-calendar.mjs` を実行します。新しい型・Userの2カラム・UserActivityテーブルを追加し、既存Postと公開済みDiaryの投稿日を日本時間で補完します。トランザクションで適用し、再実行でも記録開始日時やアクセスフラグを維持します。旧日記には公開日時がないため、過去の日記だけは作成日時を投稿日として補完します。
4. `npx prisma generate` を実行したアプリをビルド・デプロイします。DB変更を先に行ってください。
5. 本人の設定を切り替え、本人・別ユーザー・未ログインの表示を確認します。

既存アプリは追加カラムを無視できるので、アプリを旧版へ戻しても新テーブルを削除する必要はありません。アクセス記録開始前は不明として扱い、おこづかい機能のlastLoginDateを流用しません。

## 検証

### カラーパレット

プロフィール → その他の設定で、活動カレンダーの公開範囲とは独立に配色を選択できます。「くっきり」は青／朱色（ダークでは水色／オレンジ）、「グラデーション」は従来の薄緑／緑です。マーカーは丸・内部文字なしです。

「設定を保存」で閲覧者の設定として保存し、自分・他人のカレンダーの表示に使います。自分の活動を非表示にしても配色を選択でき、他人の公開カレンダーを閲覧できます。対象ユーザーの公開範囲は引き続き適用されます。初期値および未ログイン時は「くっきり」です。他の人から見た自分のカレンダーは、その人の配色設定で表示されます。

既に活動カレンダーを導入したDBでも、アプリの更新前に `node scripts/apply-activity-calendar.mjs` を再実行してください。`ActivityCalendarPalette` 型と `User.activityCalendarPalette` カラムを追加します。再実行しても保存済みの配色は変更しません。その後 `prisma generate` とビルドを行います。

### テスト

- `node --import tsx --test tests/activity-calendar.test.mjs`
- `node --import tsx --test tests/activity-palette.test.mjs`
- `node --experimental-strip-types --test tests/activity-palette-settings.test.mjs`（Node.js 24）
- `node --import tsx --test tests/activity-calendar-db.test.mjs`
- `npx tsc --noEmit`

DBテストはPGliteのインメモリPostgreSQLで実行します。接続情報は不要で、本番データベースには接続しません。

アクセス記録は表示中の画面で初回・画面遷移・復帰・1分間隔に確認し、同じ画面では記録済みの日に再送しません。バックグラウンドでは送信しません。通信失敗は次の確認で再試行します。日付やユーザーIDはサーバーが決定します。
